# Security policy

## Supported versions

Only the latest release receives security fixes. Older releases are not patched; update to the latest one.

There is no release yet; until there is, reports about the code on the `main` branch are welcome.

## Reporting a vulnerability

Report privately through GitHub's private vulnerability reporting:
**<https://github.com/burakuren/swipe-sort/security/advisories/new>**

Please do not open a public issue or discussion, and do not include real personal data in the report.
Helpful details:

- what is affected (app version, platform, backend area)
- steps to reproduce, or a proof of concept
- the impact you expect (for example, reading another user's list)

## What to expect

- An acknowledgement within 7 days. This is a one-person project, so replies can take a little while.
- An assessment and, if confirmed, a plan for a fix. You are kept up to date in the advisory.
- A fix in the next release, faster for serious issues, followed by a published advisory. You are credited
  unless you ask not to be.

Please give a reasonable time to fix the problem before you disclose it publicly. Good-faith research that
avoids other people's data and does not disrupt the service is welcome.

## Scope

In scope: the code in this repository and the official SwipeSort builds and backend. Out of scope: forks and
self-hosted copies run by others, and reports that need a rooted or compromised device.
