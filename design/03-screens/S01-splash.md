# S01 Splash

Frames: `S01-splash.html`. Generator: `tools/generators/S01-splash.py`. Brand assets: `01-foundations/brand/`.

## 1. Purpose and requirements

Show the brand for the shortest possible time while the app opens its local database, then route the person
to the right place. Never a marketing moment: no animation, no tagline, no waiting for the network.

Covers: SCR-01, BRD-01, BRD-02, BRD-05, ACC-01, ACC-02 (local data opens first), GOAL-03, COL-03 (cold
start from an invite link), PLT-01, PLT-02, PLT-03, PLT-04, PLT-17, PLT-22, PLT-23, OUT-02.

## 2. Entry points and exits

| From | How |
| --- | --- |
| App cold start | Launcher icon, notification tap, invite link (Android App Link / iOS Universal Link) |
| Web | First load of `swipesort.app` (only when the bundle takes longer than 300 ms) |

| To | When |
| --- | --- |
| S02 `S02-welcome` | First launch on this device (onboarding not completed) |
| S08 `S08-default` | Returning user (signed in or not); `S08-first-run` when no lists exist |
| S32 `S32-app` | Opened from an invite link; onboarding is skipped and offered after joining |
| Deep link target (S09, S36, S34, S25) | Opened from a notification or a list link (navigation-map §4) |
| `S01-error` | The local database cannot be opened |

The splash is replaced (not pushed): back never returns to it.

## 3. Layout and components

- **Android** (`S01-default`): Android 12+ SplashScreen API. Window background `background` token (light
  and dark variants), the app mark centered (`brand/logo-mark.svg` / `logo-mark-dark.svg`, shown at
  112 dp inside the system's icon area), and the wordmark as the branding image 48 dp above the bottom.
  `expo-splash-screen` keeps the native splash until the local database is open; the in-app continuation
  (`S01-slow`, `S01-updating`, `S01-invite`) redraws exactly the same composition so there is no jump.
- **Status block** (in-app only): Spinner (`loader-circle`, 24, `text-primary`) + `text-body
  muted-foreground` line, 40 dp below the mark. Updating uses a title, one sentence and a determinate
  Progress bar (`h-1.5`, max width 320).
- **Error** (`S01-error`): mark at 64, `text-title-2` title, one sentence, primary "Try again", ghost
  "Send a report" (opens S06 `S06-feedback`).
- **iOS** (`S01-ios`): static launch screen (storyboard generated by Expo): theme background + mark only.
- **Web** (`S01-web`, `S01-web-desktop`): mark at 80 + status text + a 4 dp indeterminate bar at the top of
  the viewport. Desktop shows it inside the centered 412 phone column.

## 4. States

| Frame | Trigger |
| --- | --- |
| `S01-default` | Every cold start on Android. Visible until the database is open (typically under 400 ms) |
| `S01-slow` | Still opening after 2 s: spinner + "Opening your lists…" |
| `S01-updating` | First start after an app update that upgrades local data; determinate progress |
| `S01-error` | Local database failed to open (corrupt file, disk full) |
| `S01-invite` | Cold start from an invite link while the invite is being checked |
| `S01-ios` | iOS launch screen |
| `S01-ios-slow` | iOS in-app continuation after 2 s (same rules as Android) |
| `S01-web` | Mobile browser, bundle load longer than 300 ms |
| `S01-web-desktop` | Desktop browser, same loader in the phone column |

## 5. Interactions, gestures and transitions

- No interaction on the splash itself (the prototype makes the whole frame a link with
  `data-action="next"` that stands in for the automatic hand-off).
- Hand-off: the splash fades out over 150 ms (`short3`, standard) as the next screen appears; reduced
  motion: instant switch. No icon animation on Android 12+ (`windowSplashScreenAnimatedIcon` is the static
  mark), so no reduced-motion variant is needed.
- The spinner rotates 1,000 ms linear; with reduced motion it is replaced by the static `loader-circle`
  icon and the text stays.
- `S01-updating` progress advances with the upgrade; it never goes backwards.
- Invite: the token is resolved in the background (max 5 s); then S32 opens. If the network is slow, S32
  shows its own loading state, so the splash never waits longer than the database.
- Error: "Try again" re-runs the open (back to `S01-slow` styling while retrying).

## 7. Accessibility

- The mark is decorative (`alt=""`); the screen reader announces the status text when it appears
  (`role="status"`, polite). The native splash is not announced.
- Error: focus moves to the title; buttons are 56 high.
- Large text: status lines wrap within a 320 max width; the mark does not scale with font size.
- Contrast: status text uses `muted-foreground` on `background` (AA in both themes).
- Reduced motion: static spinner icon; no fade on hand-off.

## 8. iOS and web differences

- **iOS**: Apple HIG asks launch screens to avoid text and branding beyond what the first screen shows, so
  the launch screen carries the mark only (`S01-ios`). Text appears only in the in-app continuation
  (`S01-ios-slow`), identical to Android.
- **Web**: there is no native splash. The HTML shell renders the loader only when JavaScript takes longer
  than 300 ms (avoids a flash). Desktop uses the S40 desktop frame (phone column centered).
- Invite links on web never show S01; they open S32 web directly.

## 9. Edge cases

- **Very slow device / huge local database** (5,000+ items in many lists): the database opens lazily;
  only list summaries are read before Home appears, so the splash stays short.
- **Data upgrade interrupted** (app killed mid-upgrade): the upgrade is transactional and restarts on next
  launch; `S01-updating` shows again.
- **Disk full**: shown as `S01-error`; "Send a report" includes the reason.
- **Invite link while not signed in**: S32 handles sign-in; the person's local lists stay untouched.
- **Invite link expired**: S32 shows its invalid-link state; the splash does not.
- **Dark mode**: both background and mark follow the system theme (and the in-app Appearance setting once
  the app is open; the native splash can only follow the system).
