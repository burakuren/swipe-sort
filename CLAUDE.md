# SwipeSort

Open-source (AGPL-3.0, docs and design CC BY 4.0) mobile app in a **public repo**: every commit is published
(ADR-0008). Later built with Expo, React Native, TypeScript, NativeWind and React Native Reusables.
**This phase is design only**: static HTML mockups delivered in `/design`. No app code yet.
The design brief carries the details; this file covers tooling and rules.

## Layout

- `design/01-foundations/` — tokens and `tailwind.config.js` (Tailwind **3**, CommonJS `module.exports`,
  theme only, no plugins that NativeWind can't use, so it can be reused in the app)
- `design/03-screens/*.html` — screen mockups containing frames
- `design/05-qa/` — `a11y-report.md` and other QA reports; screenshots and flow failure shots are generated, not tracked
- `design/assets/` — generated by `build:css` (`css/app.css` with Inter `@font-face` included, `fonts/`). Do not edit.
- `tools/` — build and QA scripts; `tools/flows/*.flow.mjs` — prototype click-through tests
- `.claude/skills/`, `.agents/` — agent skills, not tracked; restored from `skills-lock.json` (CONTRIBUTING.md).
  `webapp-testing` examples are Python; use the Node scripts here instead
- `private/` — the maintainer's private companion repo (gitignored), loaded through `CLAUDE.local.md`

## npm scripts

All run headless Chromium over `file://` URLs; no server.

```bash
npm run build:css                  # Tailwind → design/assets/css/app.css (uses foundations config if present)
npm run shots                      # every [data-frame] in 03-screens, light + dark → 05-qa/screenshots/<frame>.<theme>.png
npm run shots -- S04 S05           # only files or frame ids containing S04 or S05 (use this in subagents)
npm run shots -- S04 --theme=dark  # one theme; --scale=1 for smaller PNGs (default 2)
npm run a11y                       # axe-core (WCAG 2.2 AA) on every HTML file under /design, both themes → 05-qa/a11y-report.md
npm run a11y -- S04 --strict       # filter by path; --strict exits 1 on violations
npm run flows                      # run tools/flows/*.flow.mjs (format in tools/flows.mjs header); -- <filter>, --theme=dark
npm run qa                         # all of the above
```

Re-run `build:css` after adding new Tailwind classes, before `shots`/`a11y`.

## Conventions

- **Frames**: each phone screen is an element with a unique `data-frame="<screen-id>-<state>"`, e.g.
  `<section data-frame="S04-inbox-empty" class="w-[390px] h-[844px] …">`. IDs are unique across all files and
  become screenshot file names. Prefix screen files with their ID: `03-screens/S04-inbox.html`.
- **Theme**: `<html lang="en" data-theme="light">`; dark mode is `data-theme="dark"` on the root element. Tailwind
  `dark:` variants are wired to that attribute. Never use `prefers-color-scheme` in mockups.
- **Page skeleton**: `lang`, `<title>`, and `<link rel="stylesheet" href="../assets/css/app.css">` (relative path).
  Font family is `font-sans` (Inter Variable). No CDN links; everything must work offline.
- **Icons**: Lucide via `<i class="i-lucide-<name> size-5" aria-hidden="true"></i>` (CSS mask, takes `currentColor`).
  Names from `node_modules/lucide-static/icons/`. Icon-only buttons need an `aria-label`.
- **Prototype links**: plain relative `<a href>` between screen files; add `data-action="…"` to tappable elements for flow tests.

## Public repo

- Commit what contributors need: code, design, `GLOSSARY.md`, ADRs, build decisions, technical research.
  Material only the maintainer needs (plans with dates, testers or legal steps, name candidates, personal
  detail) goes to `private/`.
- Sample and test data is fictional: `example.com` / `example.org` emails, obviously fake phone numbers.
  Device artifacts (screenshots, exports, logs) come only from preview builds with seed data.
- Issue, PR and comment text is scrubbed of people's names, emails, numbers and list contents
  (`docs/agents/issue-tracker.md`).
- Outside input lives in GitHub Discussions; PR policy is in `CONTRIBUTING.md`.
- Secrets live in EAS, GitHub or Supabase secrets; publishable keys only in git (D-26).

## Rules

- Commit after each completed phase with a clear conventional message (`feat(design): …`, `chore: …`).
- Subagents shoot and check only their own screens (filter by screen ID) to avoid clobbering each other.
